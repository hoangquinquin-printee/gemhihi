# H-PHOTO Pattern Digitizer — Handover

## Purpose and current scope

Windows WPF/.NET 10 application for digitizing garment-pattern outlines from photographs. The current build supports image load, manual/grid calibration, constrained digitize frames, detection, point and curve editing, notches, internal/grain lines, measurements, project save/open, and DXF-AAMA export.

The application is not a Gemini binary replacement and does not use Gemini DLLs. REA material is retained only as historical behavioural evidence.

## Primary workflows

### One detail at a time

1. Load an image.
2. `File → Draw digitize frame`; draw/move/resize a rectangular frame around one detail.
3. Press Enter or choose `Enter digitize-frame dimensions`; enter actual horizontal and vertical centimetres.
4. Select `Detect pieces`.
5. Exactly the largest detected closed contour in the frame is appended as the next Piece. Its outer bounding width and height are fitted exactly to the entered cm dimensions. Existing pieces remain unchanged. The frame disappears and the new piece is selected.
6. Repeat for the next photo detail. Whole-image Detect without a frame intentionally replaces the project contour set.

### Editing

- Select mode: drag a rectangle to marquee-select vertices, including when the drag begins inside a piece. `Delete` removes only selected vertices and refuses to leave an invalid contour below three vertices.
- Single-vertex click/drag preserves single-point editing. Undo/Redo snapshots protect geometry edits.
- Line-to-curve / curve-to-line operates on the selected segment. Curve handles are editable.
- `Esc` cancels the current interactive tool.
- Wheel zoom, slider zoom, pan and hit testing share image-pixel/physical-mm transforms.

### DXF

`File → Export to DXF` writes the current DXF-AAMA implementation. Geometry is emitted in calibrated millimetres, curves are tessellated for output, and contour vertices are written contiguously before additional entities. Import compatibility must be verified with each target CAD/AccuMark build; do not state 100% compatibility from unit tests alone.

## Licensing and trial keys

The app will not open its main window until a valid offline license has been activated.

- App calculates a 24-character Machine ID from the Windows MachineGuid hash.
- The recipient sends this ID to the issuer.
- The issuer creates a signed `.hphoto-license` file with a customer name and expiry date.
- App validates RSA signature, Machine ID, and UTC expiry, then stores the license in `%ProgramData%\H-Photo\license.hphoto-license`.
- Only the public key is compiled into the app. The signing private key is outside the workspace at `Documents\H-Photo License Authority\hphoto-license-private.pem`; never send, commit, or put it in the installer.

Create a timed trial:

```powershell
.\tools\Issue-HPhotoLicense.ps1 -Customer "Customer A" -MachineId "THE_MACHINE_ID" -ExpiresUtc "2026-12-05" -OutputPath ".\Customer-A.hphoto-license"
```

This is offline machine binding, not a server-side entitlement system. A customer with administrative control can still attack a local application; use a licensing server and code signing if stronger commercial enforcement is needed.
